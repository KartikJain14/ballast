# Model Card — Ballast Overnight Buffer Sizing

SR 11-7-style summary (model risk management: conceptual soundness, ongoing
monitoring, outcomes analysis).

## Model inventory

| Field | Value |
|---|---|
| Model ID | `ballast-buffer-v1` |
| Purpose | Size the Tier0→Tier1 overnight sweep amount, hourly decision at 17:00 |
| Methodology | Closed-form newsvendor critical fractile applied to regime-conditioned (weekday / Fri-Sat) empirical quantiles of the realized overnight path-max `M` |
| Champion | `engine/policy/ballast_policy.py::BallastPolicy` |
| Challengers (shadow, in the scoreboard, not deployed) | All-cash, static buffer (grid-searched), fixed-%-of-gross, moving-average ± kσ, Miller-Orr (1966) |
| Upper bound (not deployable) | `OraclePolicy` — perfect foresight of `M`, used only to measure regret |
| Training/calibration data | 1 simulated year, 8,760 hourly rows, single generator realization |
| Owner | Treasury engineering (this repo) |

## Conceptual soundness

- The risk variable (`M`, path-max cumulative outflow) is the economically
  correct target — not hourly quantiles (undersizes the buffer) or the
  terminal net flow (undersizes when outflows front-load). Derivation and
  canonical implementation: `docs/METHODOLOGY.md` Section 2.
- The newsvendor critical fractile at this dataset's mean rates (`q* ≈
  0.986`) matches the brief's independently-stated range (97.7%-98.6%),
  cross-validating the formula against a source the model wasn't fit to.
- Day-of-week conditioning is a direct, data-driven response to a confirmed
  bimodal distribution in `M` (`docs/DATA_AUDIT.md` Section 11) — not an
  assumed feature.

## Known limitations (stated plainly, not buried)

1. **Tail quantiles above ~99% are not empirically verifiable in-sample.**
   364 nights give an expected 0.36 exceedances at the true 99.9th
   percentile — any buffer above ~99% is necessarily model-based
   extrapolation. The dashboard states this wherever a q>99% buffer is shown.
2. **Small-sample quantile noise dominates the model's own regret.** The
   regret decomposition (`docs/METHODOLOGY.md` Section 8) attributes ~99% of
   the fixable gap to the oracle to forecast-error (quantile estimation
   noise from a sample of ≤180 nights per regime), not to the risk-appetite
   policy floor. This is the single most-wanted upgrade (Section "Ongoing
   monitoring" below).
3. **One generator realization.** All findings (the weekend effect, the
   structural decline, the overdraft-trap economics) come from a single
   simulated year. They are internally consistent and cross-check against
   the brief's own independent numbers, but have not been validated against
   a second independent year.
4. **The model does not observe market-flow coupling, because there isn't
   any in this data.** Cross-correlation between net flow and equity
   returns/rate changes is ≈0 (`docs/DATA_AUDIT.md` Section 10) — we did not
   engineer a flight-to-safety feature the data doesn't support.
5. **Overdraft is unlimited in the main scoreboard.** "100% payout success"
   is a structural property of an unconstrained waterfall, not evidence the
   model handles true capital exhaustion — the Stress Lab's finite
   `overdraft_line_cap_usd` is where that failure mode is actually tested.

## Ongoing monitoring (what a production deployment should watch)

- **Champion/challenger disagreement**: if `BallastPolicy`'s buffer and a
  shadow MovingAverage/Miller-Orr buffer diverge beyond a tolerance, that is
  a signal to fall back to the more conservative of the two (circuit
  breaker — see `docs/ROADMAP.md`).
- **Coverage drift**: track realized breach rate (fraction of nights `M`
  exceeded the buffer) against the target `1-q`; a Kupiec proportion-of-
  failures test on a rolling window flags miscalibration.
- **Structural decline trend**: the dataset's -$2.53B/year net-outflow trend
  is a business signal (declining deposit franchise), not something this
  model can or should try to fix — but it should be surfaced to Treasury/CFO,
  since it changes how aggressively the buffer should be sized over time
  (shrinking capital base = less margin for error).

## Outcomes analysis

Full-year regret vs. the perfect-foresight oracle: **$590,040** (`make
replay` + `make precompute`, `reports/dashboard_cache.json::regret_summary`),
decomposed as $5,239 policy-conservatism, $584,801 forecast-error, $0
capital-constrained-regret (but $4.14M of *absolute*, irreducible cost on
66 capital-constrained nights that no policy — oracle included — could avoid).
Capture ratio vs. the best-tuned naive baseline: see `docs/RESULTS.md`
(regenerated by `make replay`, not hand-typed).

## What Ballast does NOT do (said explicitly, not left implicit)

- Does not forecast or hedge the secular deposit-base decline — that's a
  business/growth lever, not a treasury-ops one.
- Does not use the Tier2 bond sleeve by default (tested, found net-negative
  at this dataset's realized rate path — `docs/DECISIONS.md` D9).
- Does not use Tier3 equities for operational liquidity at all (brief-
  mandated: real banks generally cannot park customer liquidity in equities).
- Does not provide a probability-one guarantee against overdraft — it
  provides a priced, cost-ordered waterfall and a quantified, honestly-
  caveated breach rate.
